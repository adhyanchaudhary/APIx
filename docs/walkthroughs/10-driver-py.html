Walkthrough 10: src/scraper/driver.py

The browser launcher — opens Chromium, gives it to the scraper, then closes it safely
← PreviousNext →

What does this file do?

This file is the browser manager. It does 3 things:

  • 1. Opens a Chromium browser (like Chrome but automated)
  • 2. Hands it to the scraper so it can visit Google Flights
  • 3. Closes everything safely when done — even if the scraper crashes

It's only 47 lines but packs in some advanced Python concepts. Let's break each one down.

Analogy: A car rental service

Imagine you're renting a car to drive somewhere:

• The rental desk = this file (driver.py)

• The car = Chromium browser

• The driver = the scraper (google_flights.py)

The rental desk gives you the car, you drive it, and when you return it — the desk takes the keys, cleans the car, and parks it. Even if you crash, the desk handles the cleanup.

This file is the rental desk. It opens the browser, hands it over, and closes it no matter what happens.

What is Playwright and why do we need it?

Playwright is a Python library that controls a real web browser through code. Instead of you clicking buttons and typing URLs, Playwright does it automatically.

Why not just use requests (which fetches web pages)? Because Google Flights loads flight data using JavaScript after the page opens. A simple HTTP request can't run JavaScript — you need a real browser.

0 Before we read the code — Understanding the browser hierarchy
Playwright has 4 layers. Each one contains the next, like Russian nesting dolls. Understanding this hierarchy makes the code much easier to follow.

1. Playwright (pw)

The master controller. Launches browsers. Created by async_playwright().

2. Browser

A Chromium instance. Like opening Chrome. Created by pw.chromium.launch().

3. Browser Context

An isolated session (like an Incognito window). Has its own cookies, history, settings. Created by browser.new_context().

4. Page

One tab. Navigates to URLs, reads content. Created by context.new_page(). The scraper works with this.

# How they nest inside each other: Playwright └── Browser (Chromium) └── Browser Context (Incognito window) ├── Page (Tab 1) ← scraper uses this ├── Page (Tab 2) └── Page (Tab 3)

Concept: What is "async" and "await"?

Normal code (synchronous): Do one thing, wait for it to finish, then do the next thing.

# SYNCHRONOUS (slow) page.goto("google.com") # Wait 3 seconds for page to load... page.goto("flights.com") # Then wait 3 more seconds... # Total: 6 seconds

Async code: Start something, and while waiting, do other useful work.

# ASYNC (fast) await page.goto("google.com") # Start loading, wait... await page.goto("flights.com") # Start loading, wait... # Total: still 6 seconds (Playwright handles the waiting)

The real benefit: If we wanted to scrape 12 routes, async lets us open multiple tabs simultaneously instead of one-by-one. For now, we only use one tab — but the code is ready for parallel scraping.

In short: async def = "this function might need to wait for something." await = "wait here, but don't block other code."

Concept: What is a "context manager" (the with / async with pattern)?

A context manager is a pattern that guarantees cleanup. It works in 3 steps:

# STEP 1: Open (setup) # STEP 2: Use (do work) # STEP 3: Close (cleanup) — ALWAYS runs, even if step 2 crashes # Regular context manager (sync): with open("file.txt") as f: data = f.read() # If this crashes, the file STILL gets closed # Async context manager (what this file uses): async with create_browser_context() as context: page = await context.new_page() # If this crashes, the browser STILL gets closed

Analogy: Opening a hotel room

• Check-in = async with opens the door

• Staying in the room = the code inside the block runs

• Check-out = finally block closes the browser

Even if you leave in a hurry, the hotel still processes your checkout. The finally block is your automatic checkout.

3 load_scraper_config() — Reading settings from YAML
def load_scraper_config() -> dict: with open(CONFIG_PATH) as f: return yaml.safe_load(f)["scraper"]
What this does: Reads the scraper.yaml file and returns the scraper section as a Python dictionary.
# What scraper.yaml contains: scraper: headless: false viewport_width: 1280 viewport_height: 900 user_agent: "Mozilla/5.0 ..." page_load_timeout: 30 # What this function returns (a Python dictionary): { "headless": False, "viewport_width": 1280, "viewport_height": 900, "user_agent": "Mozilla/5.0 ...", "page_load_timeout": 30 }
Why ["scraper"]? The YAML file has a top-level key called scraper:. We only want the settings under it, not the whole file. ["scraper"] extracts just that section.

5 Step 1: Launch Playwright and open the browser
async with async_playwright() as pw: browser: Browser = await pw.chromium.launch( headless=cfg.get("headless", True), )
Line 1: async with async_playwright() as pw: — Starts the Playwright engine. pw is now the master controller. The async with ensures Playwright shuts down cleanly when we're done.
Lines 2-4: await pw.chromium.launch(headless=...) — Launches the Chromium browser. headless=False means you'll SEE the browser window on your screen. headless=True means it runs invisible in the background.
# From scraper.yaml: headless: false # You can see the browser window # If set to true: headless: true # Runs invisible, faster but can't watch it

What does "headless" mean?

Headless = no visible window. The browser runs entirely in the background — you can't see it. It's faster and uses less memory.

Headed = visible window. You can watch the browser open, navigate, and scrape. Great for demos and debugging.

Right now we have headless: false so you can see it working when you run the scraper.

6 Step 2: Create a browser context (Incognito window)
context: BrowserContext = await browser.new_context( viewport={ "width": cfg.get("viewport_width", 1280), "height": cfg.get("viewport_height", 900), }, user_agent=cfg.get("user_agent"), )
What this does: Creates an isolated browser session — like opening an Incognito window in Chrome. This context has its own cookies, history, and settings, separate from any other session.
# From scraper.yaml, these settings get used: viewport_width: 1280 # Window width in pixels viewport_height: 900 # Window height in pixels user_agent: "Mozilla/5.0 (Windows NT 10.0; Win64; x64)..." # Makes us look like a real Chrome browser

What is a "user agent"?

When your browser visits a website, it sends a "user agent" string — a text that says "I'm Chrome 120 on Windows 10." Websites use this to detect bots.

By setting a realistic user agent, Google Flights thinks we're a real person browsing, not a script. It's like wearing a disguise.

7 Step 3: Set the timeout
context.set_default_timeout(cfg.get("page_load_timeout", 30) * 1000)
What this does: Sets the default timeout for all page operations to 30 seconds. If any action (like loading a page or finding an element) takes longer than 30 seconds, Playwright will throw an error instead of waiting forever.
# From scraper.yaml: page_load_timeout: 30 # 30 seconds # The code multiplies by 1000 because Playwright uses milliseconds: # 30 seconds × 1000 = 30,000 milliseconds # Why? Because most web APIs use milliseconds, not seconds. # 30,000 ms = 30 s — same thing, different units.
8 Step 4: Hand over the context + cleanup
log.info("Browser context created") try: yield context finally: await context.close() await browser.close() log.info("Browser closed")
This is the most important part of the file. Let's go line by line:
yield context # ← THE MAGIC LINE

What does "yield" do here?

yield is like saying: "Here's the browser context — go use it. I'll pause here and wait for you to finish."

After yield, the function pauses. The code that called this function now has the context and can create pages, navigate to URLs, scrape data — whatever it needs.

When the caller is done (or crashes), execution resumes right after yield — and hits the finally block.

The try/finally pattern:
try: yield context # Give context to the caller. Pause here. # ... caller does its work ... # ... could take 5 seconds or 5 minutes ... finally: # ← THIS ALWAYS RUNS await context.close() # Close all tabs await browser.close() # Close the browser log.info("Browser closed") # Print confirmation

Analogy: A vending machine

• You put in money → machine gives you a snack (that's yield)

• You eat the snack

• When you walk away, the machine resets itself automatically (that's finally)

Even if you trip and fall while eating, the machine still resets. The finally block is the automatic reset.

Why close context AND browser separately?

context.close() = Closes all tabs/cookies in this session

browser.close() = Shuts down the Chromium process entirely

You need to close both because the context is inside the browser. If you only close the context, the browser process keeps running in the background (eating RAM). Closing the browser kills the process completely.

9 Full execution timeline — What happens when you run it
When the scraper calls this function, here's the exact sequence:

1. Load config

Reads scraper.yaml. Gets headless, viewport, user_agent, timeout settings.

2. Start Playwright

async_playwright() starts the automation engine.

3. Launch Chromium

pw.chromium.launch() opens a Chromium browser window (visible since headless=false).

4. Create context

browser.new_context() creates an Incognito-like session with 1280×900 viewport and custom user agent.

5. Set timeout

All page operations will timeout after 30 seconds.

6. Log "Browser context created"

Prints confirmation to terminal.

7. yield context → SCRAPER TAKES OVER

Function pauses. The scraper creates pages, visits Google Flights, scrapes data...

8. yield returns → BACK TO THIS FUNCTION

Scraper finishes (or crashes). Execution resumes here.

9. context.close()

Closes all tabs and the Incognito session.

10. browser.close()

Kills the Chromium process. Frees memory.

11. Log "Browser closed"

Prints confirmation. Done.

10 How other code uses this file
The scraper (google_flights.py) calls this function like this:
from src.scraper.driver import create_browser_context async with create_browser_context() as context: page = await context.new_page() # Create a new tab await page.goto("https://google.com") # Visit Google Flights # ... scrape flight data ... # After the "async with" block ends, the browser is automatically closed. # You don't need to remember to close it — it's guaranteed.

The full call chain

When you run python src/test_scraper.py:

test_scraper.py → google_flights.py (calls create_browser_context) → driver.py (opens browser) → Chromium (the actual browser) → visits google.com/travel/flights → scrapes aria-labels → returns flight data → driver.py (closes browser) → google_flights.py (saves to database) → test_scraper.py (prints results)
