The database blueprint — defines what tables exist and how to talk to them

What does this file do?

This file is the blueprint for our database. It defines 5 tables (like Excel sheets) and gives us 2 functions to connect to them.

  • It defines what columns each table has (the schema)
  • It creates the tables if they don't exist yet
  • It opens connections so other code can read/write data

Analogy: Think of it like a filing cabinet

Imagine a filing cabinet with 5 folders. This file tells you:

1. What each folder is called (table name)

2. What kind of paper goes in each folder (column definitions)

3. How to open the cabinet (connection functions)

The cabinet itself is a single file on your computer: data/apix.db

1 Imports — Getting the tools we need
import sqlite3 # Python's built-in SQLite library from pathlib import Path # For working with file paths
What is SQLite? It's a database that lives in a single file on your computer. No server to install, no passwords to set up. Just one file: data/apix.db. Python already has it built in — no pip install needed.

Why SQLite and not MySQL/PostgreSQL?

For a hackathon prototype, SQLite is perfect because:

• Zero setup — no server to install or configure

• Portable — just copy the .db file and it works

• Fast enough — handles millions of rows, way more than we need

• No permissions — anyone can read/write immediately

What this does: Builds the full path to our database file. Let's break it down step by step:

Why not just type the full path?

If you hardcode C:\Users\LENOVO\Desktop\SIH-2026\data\apix.db, it only works on YOUR computer. By using __file__, it works on any computer — Windows, Mac, Linux, wherever the project is cloned.

4 Table 1: raw_flights — Where scraped data lands first
RAW_FLIGHTS = """ CREATE TABLE IF NOT EXISTS raw_flights ( id INTEGER PRIMARY KEY AUTOINCREMENT, scrape_date TEXT NOT NULL, route TEXT NOT NULL, origin TEXT NOT NULL, dest TEXT NOT NULL, carrier TEXT, flight_no TEXT, depart_time TEXT, arrive_time TEXT, duration_mins INTEGER, stops INTEGER, base_fare REAL, taxes REAL, total_fare REAL, currency TEXT DEFAULT 'INR', lead_window_days INTEGER NOT NULL, scrape_timestamp TEXT NOT NULL ); """
What this does: This is a string (stored in the variable RAW_FLIGHTS) containing SQL code. When executed, it creates a table called raw_flights with 17 columns. The IF NOT EXISTS means if you run this 10 times, it won't error — it just skips creation if the table already exists.
Why is this in a Python string instead of being run directly? Because we want Python to create the table for us automatically when the program starts. We don't have to open a database tool and run SQL manually.

What is an index?

An index is a single number that tracks how prices change over time.

Day 1: Index = 100.00 (the starting point — always 100)

Day 7: Index = 103.54 → prices went up 3.54%

Day 30: Index = 98.20 → prices went down 1.8%

Just like how the Sensex/Nifty tracks the stock market — our index tracks airfare.

7 init_db() — Creating all tables
def init_db(db_path: Path | str | None = None) -> None: """Create all tables if they don't exist.""" path = Path(db_path) if db_path else DB_PATH path.parent.mkdir(parents=True, exist_ok=True) conn = sqlite3.connect(str(path)) try: for ddl in [RAW_FLIGHTS, CLEANED_FLIGHTS, DAILY_INDEX, WEEKLY_INDEX, MONTHLY_INDEX]: conn.execute(ddl) conn.commit() finally: conn.close()
What this function does, step by step:
# Step 1: Figure out which database file to use path = Path(db_path) if db_path else DB_PATH # If someone passed a custom path, use it. Otherwise use the default. # Step 2: Make sure the data/ folder exists path.parent.mkdir(parents=True, exist_ok=True) # Creates the "data" folder. If it already exists, don't error. # Step 3: Open the database file conn = sqlite3.connect(str(path)) # Like opening a file. If apix.db doesn't exist, SQLite creates it. # Step 4: Create all 5 tables for ddl in [RAW_FLIGHTS, CLEANED_FLIGHTS, DAILY_INDEX, WEEKLY_INDEX, MONTHLY_INDEX]: conn.execute(ddl) # Run the CREATE TABLE SQL conn.commit() # Save changes (like pressing Ctrl+S) # Step 5: Close the connection conn.close() # Always close when done!

Why the try/finally pattern?

Think of it like this:

• try: = "Try to do this work..."

• finally: = "No matter what happens (even if there's an error), ALWAYS do this."

We always want to close the database connection, even if something crashes. The finally block guarantees that.

8 get_connection() — Opening the database for other code
def get_connection(db_path: Path | str | None = None) -> sqlite3.Connection: """Return a live connection to the database.""" path = Path(db_path) if db_path else DB_PATH path.parent.mkdir(parents=True, exist_ok=True) return sqlite3.connect(str(path))
What this does: Opens the database and gives the connection back to whoever called it. The scraper, cleaner, and indexer all use this function to talk to the database.

init_db() vs get_connection() — What's the difference?

init_db() = Creates the tables (run once at the start)

get_connection() = Opens the database for reading/writing (run many times)

Think of it like: init_db builds the house, get_connection opens the door.

# How other code uses it: from src.storage.database import get_connection conn = get_connection() # Open the database conn.execute("SELECT * FROM raw_flights") # Query it conn.close() # Close when done
9 The main block — Running this file directly
if __name__ == "__main__": init_db() print(f"Database created at: {DB_PATH}")
What this does: If you run python src/storage/database.py directly, it creates all 5 tables and prints the path. But if another file imports this module (like from src.storage.database import init_db), this block does NOT run — only the imports happen.

The Big Picture

Data flows through the tables in order:

raw_flights
→
cleaned_flights
→

→
weekly/monthly
  • raw_flights: Scraper dumps everything here (messy, may have duplicates)
  • cleaned_flights: After cleaning (no duplicates, outliers flagged, quality scored)
  • daily_index: The APIx index number — one row per route per day
  • weekly_index: Same but averaged over a week
  • monthly_index: Same but averaged over a month
