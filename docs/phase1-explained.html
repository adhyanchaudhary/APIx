The Files We Built

1 src/scraper/base.py - The Contract

What it does
Defines a rule: "Every scraper must have a fetch_flights() method." This way, if we ever switch from Google Flights to MakeMyTrip, we know exactly what method to implement.
Like a job description that says "whoever gets hired must be able to do X, Y, Z." Different people (scrapers) can fill the role, but they all do the same things.

2 src/scraper/driver.py - The Browser Launcher

What it does
Opens an invisible Chromium browser using Playwright. Reads settings from config/scraper.yaml (viewport size, user agent, timeouts). Gives you a "browser context" to work with.
# What the code looks like (simplified):
async with create_browser_context() as ctx:
    page = await ctx.new_page()       # open a new tab
    await page.goto("google.com")     # go to a website
    content = await page.content()    # read the page
# Browser closes automatically when done
Like renting a car for the day. You get in (create context), drive around (navigate pages), and when you're done, you return it (browser closes). The car handles all the mechanical stuff - you just steer.

3 src/scraper/google_flights.py - The Brain

What it does
The main scraper. Builds Google Flights URLs, navigates to them, finds flight data on the page, and parses it into structured records.

This is the most important file. Here's what happens inside:

The aria-label Trick

Google Flights stores each flight's complete description in a hidden text called an aria-label. We discovered this by inspecting the page's HTML. Instead of trying to find tiny elements with fragile class names, we read these rich descriptions directly.

# What Google Flights hides in each flight card:
"From 12882 Indian rupees round trip total.
 Nonstop flight with IndiGo.
 Leaves Indira Gandhi International Airport at 8:45 AM
 on Friday, September 11
 and arrives at Chhatrapati Shivaji Maharaj International Airport
 Mumbai at 11:00 AM on Friday, September 11.
 Total duration 2 hr 15 min."

# Our parser extracts:
Price:    12882 rupees
Airline:  IndiGo
Departs:  8:45 AM
Arrives:  11:00 AM
Duration: 135 minutes
Stops:    Nonstop (0)
Like finding that each product on Amazon has a complete description in its alt-text. Instead of figuring out where the price label is, where the title is, where the rating is - you just read the one description that has everything.

4 src/scraper/run_scrape.py - The Orchestrator

What it does
Loops through all 12 routes x 3 lead windows = 36 search combinations. For each one, calls the scraper, then saves results to the database.
# The loop (simplified):
for route in [DEL-BOM, BOM-DEL, DEL-BLR, ...]:     # 12 routes
    for window in [1, 7, 30]:                        # 3 lead times
        flights = scraper.fetch_flights(route, window)
        save_to_database(flights)
Like a manager who gives a list of tasks to the worker: "Check Delhi-Mumbai for 1-day, 7-day, 30-day. Then Delhi-Bengaluru for 1-day, 7-day, 30-day..." and so on for all 12 routes.

What Happens When Things Go Wrong

The scraper has a retry system because websites sometimes fail to load:

AttemptWait TimeWhat Happens
1st try3 secondsFirst attempt - most likely to succeed
2nd try6 secondsWaited longer, try again
3rd try12 secondsLast chance before giving up
Like restarting your phone when an app crashes. If it crashes again, you wait a bit longer before trying again. If it crashes a third time, you assume the server is down and move on.
The scraper also limits itself to 60 requests per hour and waits 3-8 seconds between each request. This prevents Google from blocking us for being too aggressive.

Self-Check Quiz

Q1: Why does the scraper use aria-labels instead of CSS class names?

Google Flights uses randomly-generated class names like "pIav2d" and "JMc5Xc" that change when Google updates their site. But the aria-label text ("From 12882 Indian rupees...") is stable, readable, and contains ALL the flight data in one string. It's much more reliable to parse.

Q2: Why does the scraper wait 3-8 seconds between requests?

To avoid being detected and blocked by Google. If we hit their servers too fast, they'll think we're a bot and show us a CAPTCHA or block our IP. The delay makes us look like a regular human browsing.

Q3: What is the "retry with backoff" system?

If a page fails to load, the scraper waits a bit and tries again. Each retry waits longer (3s, 6s, 12s) - this is called "exponential backoff." It gives the server time to recover without overwhelming it.

Q4: Why does the browser close automatically?

The async with statement ensures the browser is properly closed even if an error occurs. This prevents "zombie" browser processes from eating up your computer's memory.
