1. The Problem

Airfares on India's metro routes are volatile and opaque. Travelers have no objective way to know whether a fare is high, normal, or cheap, and policy teams lack a single official number that tracks how the cost of domestic air travel is moving over time.

2. The Solution — APIx

APIx is an Airfare Price Index built like a Laspeyres consumer-price index: it scrapes live fares for a fixed basket of 12 directional routes, collapses them to the lowest fare per route per day, and tracks each route's price relative to a base day. The result is a weighted aggregate number — the same technique used for CPI and WPI, applied to airfares.

APIx(t) = Σ [ Pi(t)  /  Pi(0) × wi ] × 100

Where Pi(t) is the lowest fare on route i on day t, Pi(0) is the lowest fare on the base day, and wi are route weights derived from DGCA traffic share (sum ≈ 1.0). Base day is always 100.

4. The Route Basket & Weights

Four cities — Delhi (DEL), Mumbai (BOM), Bengaluru (BLR), Chennai (MAA) — form six city-pairs; each pair is flown in both directions, giving 12 directional routes. Each route is scraped at three advance-purchase windows: T+1, T+7, T+30.

Weights live in config/indexer.yaml and are normalised to sum 1.0 at load time. Routes without data on a day are omitted — their weight stays unclaimed and is never re-distributed (no re-normalisation per day).

8. How to Run

pip install -r requirements.txt
playwright install chromium            # once

python -m src.scraper.run_scrape       # batch: raw_flights   (12 routes x 3 windows)
python src/cleaner/clean.py            # clean: cleaned_flights
python -m src.indexer.run_index        # index: daily/weekly/monthly_index

pytest tests                           # 14 tests
Note: the full scrape requires a live connection to Google Flights and rates itself to 60 requests/hour. For an offline demo, src/cleaner/test_run.py builds mock data and runs the whole Phase 2 pipeline.

9. Constraints & Acceptance Criteria

Constraints

  • Respect the source: hard cap of 60 requests/hour, random 3–8s delays, 3 retries with exponential backoff (×2).
  • Offline reproducibility: every DataFrame function is unit-testable without the network; fixtures replace scrapes in tests.
  • Single source of truth: all routes, weights, and settings live in config/*.yaml.

Acceptance criteria

  1. System scrapes all 12 routes at 3 windows and stores every flight in raw_flights.
  2. Cleaning removes duplicates, null fares, and flags IQR outliers (1.5×) with a per-row quality score.
  3. The indexer writes daily_index, weekly_index, monthly_index; the base day is 100 for every route and window.
  4. Re-running the same day replaces rather than duplicates index rows.
  5. All weight sums check to 1.0 and route weights match config/indexer.yaml.
