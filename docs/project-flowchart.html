APIx Project — How the Full System Works

Twelve directional city-pairs are scraped from Google Flights, cleaned, and blended into a 36-cell weighted price index (daily / weekly / monthly), then evaluated with estimator-stability research.

Flow & Legend

Phase 0 — Config Phase 1 — Scraper Phase 2 — Cleaning Phase 3 — Index Builder Phase 4 — Research / Models Storage (SQLite data/apix.db)

Arrows show data flow. Each box lists the script(s) that do the work and the key settings that shape it.

The Pipeline

Phase 0 · Configuration & Storage
Config files — the "what" of the index
config/routes.yaml · config/scraper.yaml · config/indexer.yaml · .env
  • 4 cities (DEL, BOM, BLR, MAA) with DGCA weight shares
  • 12 directional routes (6 city-pairs × 2 directions)
  • Scrape horizon: 30 days of departure dates ahead
  • Lead windows: 1 / 7 / 30 days before departure
  • 36-cell basket: window weights 0.20 / 0.30 / 0.50, route weights normalised to sum 1.0
  • Estimators: aggregation weighted_trimmed_mean (CPI-style), rolling mean, price method median
  • Cleaner: IQR outlier method (×1.5), null-fare drop
  • Scraper: 60 req/hour max, 3–8 s delay, 3 retries
Storage layer
src/storage/database.py · .env
  • Creates the apix.db schema on first use
  • Connection + init helpers used by every stage
  • 5 tables: raw_flights, cleaned_flights, daily_index, weekly_index, monthly_index

Phase 1 · Scraper
Google Flights scraper
src/scraper/google_flights.py · src/scraper/base.py · src/scraper/driver.py

Opens Playwright (Chrome, human-like), builds the search URL for each route × departure date, and parses fares out of the page's aria-label attributes.

Batch runner / smoke test
src/scraper/run_scrape.py · src/scraper/run_smoke.py
  • Loops 12 routes × 30 horizon days every run (plus the t+1/t+7/t+30 anchor windows)
  • Enforces rate limits, jittered delays, and exponential backoff retries
  • run_smoke.py = one-route sanity check of the live scraper
  • Writes every scrape into raw_flights
▼
apix.db → raw_flights
  • Every scraped fare: route, origin, dest, carrier, times, base/taxes/total fare, currency, lead_window_days, quality_score, dedup_hash
written by: scraper | read by: cleaner

Phase 2 · Cleaning
Cleaning pipeline
src/cleaner/clean.py · src/cleaner/pipeline.py
  • Cast columns to the right types
  • Deduplicate rows on dedup_hash
  • Drop null fares (per config: null_fare_action: drop)
  • Flag outliers with the IQR fence (×1.5) — is_outlier=1, kept but excluded from prices
  • Quality score per row
Verification
src/cleaner/check_db.py · src/cleaner/test_run.py · src/cleaner/mock_data.py

check_db.py prints raw vs cleaned counts and outliers; test_run.py exercises the pipeline on deliberately-defective mock data.

▼
apix.db → cleaned_flights
  • Deduped, clean rows, one fare per scrape with outlier flag & quality score
written by: cleaner | read by: indexer

Phase 3 · Index Builder (the core)
1 · Collapse fares to cells
src/indexer/api_index.py → route_price_per_day()
  • One price per (route, lead_window, date) cell = median of the scraped fares
  • Outlier-flagged rows are excluded from the price
  • Carry-forward fills calendar gaps with the last known fare
2 · Daily composite (36-cell basket)
compute_daily_index()
  • Shared base date = first date with any data; that day's composite = 100
  • Each cell prices itself against its own base fare; late-starting cells join at 100
  • Cell weight = route weight × window share
  • Headline = aggregate() over present cells — a single number per date (weighted_mean / trimmed / median)
3 · Weekly & monthly rollups + save
compute_rolling_index() · write_index()
  • 7-day rolling → weekly_index, 30-day rolling → monthly_index
  • Same estimator choice (mean / trimmed_mean / median), min_periods=1
  • Re-running a date overwrites instead of duplicating
Key takeaway: the daily APIx headline is a single weighted composite over the 36 cells (12 routes × 3 lead windows). Window shares (0.2 / 0.3 / 0.5) mean month-ahead prices dominate; median cell pricing stops one ultra-cheap fare from dragging a cell down.

Phase 4 · Research, Reporting & Models
Synthetic data (offline research)
src/indexer/synthetic.py

Seeded generator shaped like real scrapes (drift, weekend bumps, spikes, coverage gaps) so the estimator work is reproducible before real 30-day data arrives.

Stability metrics + report
src/indexer/metrics.py · src/indexer/report.py
  • Compares aggregation & rolling estimators across windows
  • Measures day-to-day volatility of the headline
  • Route sensitivity = headline move when a route loses data (robustness)
  • Weight elasticity = headline move per +0.01 weight (which DGCA weights matter)
  • Falls back to synthetic when real data is too sparse (<3 routes / <5 dates)
Optional fare-direction model
src/models/price_predictor.py

A standalone TensorFlow classifier (input: 20 features → 2 × 64–32 ReLU+Dropout layers → softmax over DOWN / STABLE / UP). Not wired into the MVP — future Phase-2 work.
