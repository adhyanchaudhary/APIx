Single-Request Detail

What happens inside fetch_flights() (google_flights.py):

  • URL builder — encodes origin, destination, travel date, and lead window into the Google Flights search URL.
  • Wait for results — up to 15s for the results container.
  • Collect aria-labels — page.evaluate() runs JS inside the browser tab to read every flight card's aria-label.
  • Parsing — regex extractors pull departure/arrival times, duration, stops, carrier, and fare from each label.
  • Validation — each result becomes a FlightRecord (Pydantic): positive fare, stops 0–5, window 1–90.
  • Politeness — sleeps a random 3–8s before the next request; retries transient failures.

Quality Controls

60 req/hour cap3–8s random delay3 retries, ×2 backoffPydantic validationbatch SQL insertsper-run summary

Every request is throttled, retried, and validated. Failures are counted per route×window so one bad request never aborts the whole run.

Key takeaway: 36 polite, validated requests fill raw_flights. Nothing here touches cleaning or index math — that is Phase 2's job.
