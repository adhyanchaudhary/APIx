Real-time Airfare Price Index (APIx)

SIH 2026 — Automated Airfare Data Collection, Indexing & Prediction Platform

Problem

  • MoSPI measures airfare inflation via manual price collection from limited physical ticketing outlets. Over 90% of domestic fares are sold online.
  • Indian airfares swing 200-400% within a single day due to dynamic pricing. Monthly CPI surveys cannot capture this.
  • RBI needs high-frequency, route-specific fare data for monetary policy. Current data is weeks old and unrepresentative.
  • The CPI airfare basket misses OTA-only deals, dynamic surcharges, and coupon-based pricing entirely.

Our Solution

  • Automated Playwright scraper pulls live prices from Google Flights daily — 12 city-pairs, 3 purchase windows (T+1, T+7, T+30).
  • Pandas cleaning pipeline deduplicates, handles missing data, detects statistical outliers, scores data quality.
  • APIx weighted basket index computed daily/weekly/monthly using DGCA traffic-share weights (Laspeyres-style, base period = 100).
  • ML prediction layer (Phase 2): neural network trained on accumulated price history to forecast weekly fare movements per route.

Phase 2 Data Cleaning

raw_flights → dedup → outlier detection → quality scoring → cleaned_flights

1

Deduplication

MD5 hash computed on:

route | carrier | depart_time
| total_fare | lead_window_days

Duplicate rows (same flight scraped twice) removed before any analysis.

→
2

Missing Fares

Two strategies, configurable in indexer.yaml:

  • drop — delete rows with null total_fare
  • forward_fill — impute from same (route, lead) group using pandas ffill()
→
3

Outlier Detection (IQR)

Grouped by (route, lead_window_days):

Q1 = 25th percentile
Q3 = 75th percentile
IQR = Q3 - Q1
Lower bound = Q1 - 1.5 * IQR
Upper bound = Q3 + 1.5 * IQR

Fares outside bounds → is_outlier = 1, excluded from indexing.

→
4

Z-score (Alt.)

Alternative method via outlier_method: "zscore":

z = (x - mu) / sigma
|z| > 3.0 → outlier

Both methods use same iqr_multiplier / zscore_threshold config.

→
5

Quality Score

Every row starts at 1.0. Deductions:

  • -0.20 per missing core field (carrier, times, duration, fare)
  • -0.10 if stops not in {0, 1, 2}
  • Clamped to [0, 1]

Rows below a quality threshold are excluded from indexing.

→
6

Write

Appends to cleaned_flights with extra columns:

quality_score
is_outlier
dedup_hash
scrape_date

Phase 3 APIx Index Construction

cleaned_flights → route averages → weighted basket → daily_index (single layer shown)

1

Route Price per Day

For each scrape_date and route, compute average fare (outliers excluded):

route_price = AVG(total_fare)
  WHERE is_outlier = 0
  GROUP BY scrape_date, route

Produces one price point per route per scrape day.

→
2

Base Period

First scrape date with data across all routes is the base day. Base period setting: "first_available".

base_price(route) =
  AVG(total_fare on base_date)
  WHERE route = X

Base day: every route index = 100.

→
3

Route Index

Laspeyres-style price index per route, per day:

route_index =
  (route_price / base_price) * 100

Measures how much that route's average fare has changed from the base period.

→
4

DGCA Weights

City traffic-share weights (DGCA approx.):

DEL  0.30
BOM  0.25
BLR  0.25
MAA  0.20

Route weight derived from origin + destination city weights.

→
5

Aggregate Index

Weighted average across all routes:

aggregate_index =
  SUM(route_index * weight)
  / SUM(weight)

Single composite number per day representing overall domestic airfare level. This is the APIx.

  • weekly_index and monthly_index follow the same schema, just grouped over wider windows
  • min_data_points: 30 — index is considered valid only after 30+ days of data

Phase 4 Price Prediction Model

Binary classifier — predicts P(price increases in upcoming week) per flight. Deep neural network with ReLU activations, dropout regularization, softmax output.

Training Setup

ComponentChoice
OptimizerAdam (mini-batch gradient descent), lr = 1e-3
