Environment, requirements, YAML configs, Pydantic schemas, and the SQLite layer

The Big Picture

Phase 0 is everything the pipeline stands on: the settings (.env), the dependency manifest (requirements.txt), the three configuration files (config/*.yaml) that define the route basket and weights, the typed data models (schemas.py), and the five SQLite tables (database.py). It contains zero business logic — just definitions that the scraper, cleaner, and indexer all read.

1. .env — Runtime Settings (11 lines)

.env
Not committed (in .gitignore). Loaded by python-dotenv.
# Browser installation
PLAYWRIGHT_BROWSERS_PATH=0

# Logging
LOG_LEVEL=INFO

# Scraper behaviour
SCRAPER_MAX_REQUESTS_PER_HOUR=60
SCRAPER_DELAY_MS[0..1]=3000..8000
SCRAPER_MAX_RETRIES=3
  • PLAYWRIGHT_BROWSERS_PATH=0 keeps browser binaries inside the virtual environment instead of the global cache.
  • LOG_LEVEL=INFO shows normal progress but hides DEBUG noise.
  • Rate-limit values mirror config/scraper.yaml: max 60 requests/hour, random 3–8s delays, max 3 retries.

2. .gitignore — What NOT to Commit (30 lines)

.gitignore
Keeps secrets, generated data, and tooling noise out of version control.
  • Python: __pycache__/, *.pyc, *.pyo, build metadata.
  • Secrets & envs: .env, venv/, .venv/.
  • Generated data: data/*.db (regenerated by the pipeline).
  • Editors/OS: VS Code, JetBrains, Vim swap files, OS junk.

4. config/scraper.yaml — How the Scraper Behaves (21 lines)

config/scraper.yaml
scraper:
  max_requests_per_hour: 60
  delay_between_requests: {min_seconds: 3, max_seconds: 8}
  max_retries: 3
  backoff_multiplier: 2          # waits 3s, 6s, 12s
  headless: false
  viewport_width: 1280
  viewport_height: 900
  user_agent: "Mozilla/5.0 ... Chrome/120.0.0.0 Safari/537.36"
  page_load_timeout: 30
  element_wait_timeout: 15

Rate limiting, a 3–8s random delay, and 3 retries with ×2 backoff keep the scraper polite. headless: false makes failures easier to debug during development.

5. config/routes.yaml — The Route Basket (59 lines)

config/routes.yaml
cities:
  DEL: {name: "New Delhi",  code: DEL, weight: 0.30}
  BOM: {name: "Mumbai",     code: BOM, weight: 0.25}
  BLR: {name: "Bengaluru",  code: BLR, weight: 0.25}
  MAA: {name: "Chennai",    code: MAA, weight: 0.20}

routes:            # 6 pairs x 2 directions = 12 directional routes
  - DEL-BOM        - BOM-DEL
  - DEL-BLR        - BLR-DEL
  - DEL-MAA        - MAA-DEL
  - BOM-BLR        - BLR-BOM
  - BOM-MAA        - MAA-BOM
  - BLR-MAA        - MAA-BLR

lead_windows: [1, 7, 30]          # T+1, T+7, T+30

City weights are NOT the index weights. City weight is the city's share of national passenger traffic (used only as a description). The index weights live in config/indexer.yaml.

6. config/indexer.yaml — Index Formula & Weight Basket (28 lines)

config/indexer.yaml
index:
  base_period: "first_available"   # index = 100 on first day with data
  round_to: 2
  min_data_points: 1
  weights:
    DEL-BOM: 0.10   BOM-DEL: 0.10
    DEL-BLR: 0.09   BLR-DEL: 0.09
    DEL-MAA: 0.06   MAA-DEL: 0.06
    BOM-BLR: 0.10   BLR-BOM: 0.10
    BOM-MAA: 0.08   MAA-BOM: 0.08
    BLR-MAA: 0.07   MAA-BLR: 0.07

cleaning:
  outlier_method: "iqr"
  iqr_multiplier: 1.5              # Q1 - 1.5*IQR  to  Q3 + 1.5*IQR
  zscore_threshold: 3.0
  null_fare_action: "drop"         # or "forward_fill"

These 12 weights are normalised to sum 1.0 by load_route_weights() and used in the Laspeyres basket. The cleaning: section drives the outlier logic in src/cleaner/clean.py.

8. src/storage/database.py — SQLite Layer (120 lines)

src/storage/database.py (120 lines)

One database file, five tables:

TableContents
raw_flightsEvery scraped flight (16 columns, id + scrape_date + route + fares + window)
cleaned_flightsSame + quality_score, is_outlier, dedup_hash, extraction_batch_id
daily_indexindex_date, lead_window_days, route, weight, route_price, route_index, aggregate_index, base_period
weekly_index7-day rolling mean of daily (same columns)
monthly_index30-day rolling mean of daily (same columns)

 

Note: all three index tables carry lead_window_days INTEGER NOT NULL — this is required by the idempotent upsert in api_index.write_index() (DELETE + INSERT per date/window pair).
Key takeaway: Phase 0 is "the constitution" — every behaviour (routes, weights, rate limits, base period, outlier rules) is config-driven, and every table and model is schema-checked. Updating the weight basket is a one-line YAML change, no code involved.
